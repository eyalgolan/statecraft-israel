# Population identity foundation — #1689 steps 1–2

This is a fixture-only data/helper contract under exact `gdd-0.3` identity (R-POP-001/002/003), not a playable campaign. No production era, shipped content, catalogue or save envelope changes. The existing synthetic Attention/Arms harnesses still exercise their pre-ledger aggregate model; that does not activate population identity. A state with an initialized ledger is rejected by Simulation.Step, Preview and DelegatedTo and at direct aggregate population/resource producer boundaries before any mutation (PopulationLedger.RefuseAggregate). The guarded sites include Cities, PopulationSystem, Pools, starting forces, training, qualification/demobilisation, military/combat/prisoners, event mutation, the economy and objectives (the readers of GameState.TotalPopulation, which reads the ledger once it is initialized) and the turn resolver. Direct integration into Cities, PopulationSystem, Training, Combat, Prisoners, Pools and other systems remains held.

`PopulationLedger.CreateFixture` is internal (test assembly friend access), constructs a fresh GameState without Simulation.NewGame, validates explicit frozen location/target/captor/qualification bindings and builds inventory in source-key/ordinal order. It never converts census headcounts, historical formations, cohorts or events into people. Fixture rows are visibly synthetic, supplied in test code; no new files are loaded or hashed as content. Each reception tick is one whole reception turn, capped by the Agreed catalogue `reception.turns`; course limits are explicit synthetic target data, not production defaults.

The public read surface returns immutable records and a read-only snapshot list. Mutations require an initialized gdd-0.3 ledger. Get/count, move, explicit assignment release/change, atomic transition, replacement of history/progress/equipment, registered arrival and combat loss form the contract for later issues. Replacement cannot insert a new identity. Transition and move preserve reception, both experience tracks, profession/tier, qualification and issued-equipment facts. Capture must retain a bound home and captor and clear local assignment/location; return callers must supply a valid status/location/assignment. The helper chooses no destination, formation, exchange timing, prices or refunds.

Validation builds a candidate map first, including teacher resolution and unique issued-item ownership across both equipment categories. A referenced teacher cannot disappear or leave teaching while pupils still refer to it; future integrated operations must release/reassign references atomically before that loss/transition. No resources, RNG or cause log are involved. Explicit arrival provenance remains consumed after death. `int.MaxValue` is the allocator exhaustion sentinel; allocation refuses before changing anything. Reconcile checks the exact source/loss/living id relation. Fixture-only `nextPopulationId` allows boundary coverage without allocating billions of records.

GameState.Clone owns a copied ledger; frozen bindings and records can be shared. Canonical output covers the full binding inventory, all unit fields, source/loss records, initialization flag, scale/reception requirement and allocator in one shared Describe/Hash writer. Reference strings use invariant length-prefixed encoding with an explicit null marker; embedded delimiters cannot alias another record. All accepted reference/provenance strings reject malformed UTF-16 before admission, so UTF-8 hashing cannot collapse invalid surrogate sequences; valid supplementary characters remain lossless. Enum declaration order is never serialized. Older identities enter none of this writer. The new empty gdd-0.3 section changes unpublished schema-4 draft hashes only; no legacy/schema-3 migration or byte change is intended.

No save/reload round trip for population identity is claimed. The existing seed/content/command replay envelope is unchanged; step 3 must introduce actual identity-addressed replayable producers before population fixtures can be saved as campaigns. Captured Food selection and arrival meal timing, course/combat/prisoner integration, production initialization and all of #1704 remain held. This foundation does not implement R-POP-004 or close #1689.
