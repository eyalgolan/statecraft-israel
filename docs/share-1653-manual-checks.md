## Release eligibility and cancellation (F1/F5)

1. Open Settings → Share and wait for the preview. Use physical Enter down for 0.2–0.5 seconds, then Enter up on main Share; expect one current sheet or download. Repeat with pointer release and Instagram, then Copy. Repeat quick Enter and a hold longer than 1.5 seconds, recording actual ordering. The long hold may expire the arm; do not report it as ordinary Enter success.
2. Within the arm timeout, release Shift before Enter; Shift must do nothing and leave the arm available for Enter. Repeat Tab keyup without moving focus if physically obtainable. A real Tab focus switch is allowed to cancel the old ticket via focus-out; distinguish that from keyup filtering. Single-space and legacy `Spacebar` key values are accepted; the literal `Space` key value is ignored. If the device cannot produce a legacy/literal value, record that subcase unverified. Do not manufacture a JS event and call it trusted input.
3. Arm, press Escape **keydown**, then release Escape and Enter. Expect no old action. Repeat Close before release, focus-out before release, fresh canvas pointerdown, pointercancel if obtainable, window blur/resize/visibility change, and timeout. A subsequent release must not revive that ticket. For main Share/Copy this does not add ExternalLink's pointer rectangle/identity/button validation: main pointerup eligibility otherwise stays as before. Record drag-off separately; do not claim geometry parity. For main Share, Instagram and Copy, explicitly try pointer-arm → unrelated keyup (Shift) → pointerup: the keyup must leave the ticket armed and pointerup must act once. Then try keyboard-arm → pointerup: pointerup must act once because these arms are intentionally mode-less. Finally try eligible keyup → pointerup on the same ticket: the keyup consumes it, so pointerup must add zero actions. Keep each sequence within the timeout without intervening focus-out or a new arm; if physically unreachable, record it unverified.
4. Before 1.5 seconds expires, replace an armed main Share with each of X/Facebook/WhatsApp/Telegram/LinkedIn, then release Enter: only the current site's image-copy/download plus one site open, zero main action. Reverse the order. Repeat Instagram/site and Copy/site both directions, Share/Instagram both directions, Share/Copy, site/site, and same-control replacement. Every new arm must cancel the previous ticket. If the UI cannot produce an overlap sequence, mark it unverified/unreachable in that run; do not substitute an assumed deterministic result.
5. Where observable, deliver an old owner's focus-out/cancel/timeout after another control has armed. Only the old ticket may be cancelled; the current release must still work once. Close with a site ticket current, reopen without Send, and release: zero old actions. Dispose/rebuild the UI with an arm pending and repeat. Check for extra tabs/sheets/downloads and orphan listeners/timers through passive diagnostics if available. Include a non-share ExternalLink (for example Star) in replacement checks where physically reachable: it shares the same release slot.

## Failure reporting and attempt isolation (F2/F3/F4)

6. In a native-capable cell, obtain a real non-Abort refusal delayed beyond three seconds while the panel remains open. Expect exactly the current fallback note and one current-file download request. Repeat Instagram: only its note may appear. Current success/cancel remains silent; its Failed-only observer stays alive until failure, a new action, Close or Dispose. Cancel the sheet, wait at least five seconds, confirm no fallback, then retry. Record no-target Abort separately. If a delayed refusal cannot be obtained, leave it unverified.
7. Where capability legitimately changes from true at panel-open to false/missing/throwing at release, expect the current failure flag before the download request and then the fallback note. Use passive inspection if possible to establish flag/request ordering. Stable unsupported capability should immediately show the existing attach note and request a PNG on release. If the capability transition cannot be produced on an approved build, mark that transition unverified; do not edit host permissions or install a runner as part of this check.
8. Release share A and, only where its native promise actually remains pending, Close → recapture B → press/release B → observe non-Abort rejection A. There must be no A download, no A failure flag attributed to B and no A note. A current B refusal should request only File B and show only B's note. Repeat A rejection after B press but before B release; B resolves then A rejects; B aborts then A rejects. Repeat replacing A with Copy, Instagram and each site; Keep, Close and Dispose must invalidate A as well. If any A/B settlement ordering cannot be obtained, it remains **unverified**. No synthetic promise harness is included, and no deterministic substitute is claimed.
9. Native-sheet focus transfer after the normal release must not invalidate that same attempt: a current non-Abort refusal may still download its own file on return. Focus-out before release cancels only its still-armed ticket. Close/reopen without Send must not revive a poll or note. Switch Share → Instagram and reverse, then Copy and each site while a share result is pending: only the latest observer may report. Repeat UI disposal while the visual tree remains alive where an approved diagnostic build permits it; do not claim runtime coverage from EditMode alone.
