# GDD v0.1 Phase 5: military units, movement and combat. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (one PR at a time per track, inline, as in Phases 1 and 2). Steps use checkbox (`- [ ]`) syntax for tracking. **The owner reviews this plan before any code.** Every PR below names the owner questions it waits on. A PR does not start until those questions are answered and the answers are recorded (PR 0).

**Goal:** Make the War of Independence playable as units on the hex map. Recruits, veteran soldiers, artillery and armoured cars become sim units with an Arms cost and upkeep. Units move over terrain, roads and stacks; take the fortify, hold and attack orders; and fight under a deterministic combat rule. The Arab forces that D-G1 names become units, and an enemy AI follows a sourced script in Historical mode. The call-up and the security rung give way to the war state (D-C4). Prisoners follow the impact plan §4.3. The war objective completes on the last armistice (D-B2). Units-in-play draws the units from `State.Units`.

**Architecture:** Phase 1 built `TurnResolver` with steps 1 to 3 left as comments: "1-3. Enemy orders, combat, capture: Phase 5" (`sim/Statecraft.Sim/TurnResolver.cs`). This phase fills steps 1 and 2 and leaves step 3 (capture of settlements) to Phase 6. The `Unit` record (`GddState.cs`) already holds halutzim as `Id, Type, Q, R` in `GameState.Units`, hashed under `units[...]` only when non-empty (R-LOOP-002). Phase 5 extends that record. A new field is written to the hash only when it is not at its default, so a halutz unit hashes as before. Unit orders are standing orders, and a command carries only a *change* (spec §2.3). Unit orders cost no Attention (D-A6, decided). Paths, combat and the enemy AI are new files: `Movement.cs`, `Combat.cs` and `EnemyAI.cs`. Every preview number the UI shows comes from a public sim helper (spec §2.6).

**Tech stack:** as Phase 1: C# netstandard2.1 sim (`sim/Statecraft.Sim`), xUnit on net10.0 (`sim/Statecraft.Sim.Tests`), YamlDotNet content, Unity 6000.3.25f1 UI Toolkit (`unity/`), Python tools and policy checks under `uv`.

**Spec:** [the impact plan](../specs/2026-10-12-gdd-v0.1-impact-and-plan.md): §1.3, §1.6, §2.2, §2.3, §2.5, §2.6, §3, §4.2, §4.3, §5 groups G and C (D-C4), and §6 "Phase 5". Design of record: [docs/GDD.md](../../GDD.md) ("Population and units", "Movement and civilian actions", "Military actions and settlement control", "Objectives"). The format follows [the Phase 1 plan](2026-10-12-gdd-phase-1.md) and the Phase 2 plan (PR #568, in review; its file will be `docs/superpowers/plans/2026-10-14-gdd-phase-2.md`). Issue: #385 (part of #374). Owner decisions: #375 and [DECISIONS](../../oss/DECISIONS.md). Research: `research_notes/GDD phase 5/arab-forces-1948.md` (#419) and `research_notes/M4 war mode/war-1948.md` (#396).

## Review focus

1. **Determinism of paths and combat.**
   - The same state and orders give the same path, bit for bit, on .NET, Mono and IL2CPP.
   - A tie between equal-cost paths is broken by the stated order, never by collection order.
   - Each engagement draws exactly the documented number of RNG values, and a turn with no engagement draws none.
   - Tests: PR 5 (paths), PR 8 (draw count).
2. **Civilian harm that pays, through a loophole.**
   - No combat outcome changes a city's or locality's residents, housing, jobs or any resource in the player's favour.
   - Entering or holding a locality's hex gives nothing (Q-CIV-1).
   - Prisoners are never labour, Money, Arms or a bargaining resource, and they score only when returned.
   - Tests: PR 8 (`CombatTouchesOnlyCombatants`), PR 12 (`PrisonersAreNeverAResource`), and the property test in PR 13.
3. **Invented positions.**
   - Every starting unit in the sim names its `units_1948.yaml` row and anchor.
   - A hidden row (Oded) or an anchor outside its window starts nothing.
   - Test: PR 4.
4. **Units that vanish, duplicate or reuse an id.**
   - Recruits who finish training become units with conservation: the people in = the people out.
   - A destroyed unit leaves the state, and its id is never reused (`NextUnitId`).
   - Tests: PRs 3 and 8.
5. **The enemy AI bends the rules.**
   - Its orders go through the same validation as the player's.
   - It reads only the state, so it has no information a rule does not give it.
   - In Historical mode it never moves a unit to a position no source gives while its script still runs (Q-ENEMY-1).
   - Test: PR 10.
6. **Frame budget.** One `Step` stays under 16 ms in the WebGL player with the full starting forces of both sides (spec §2.5), and the units layer rebuild stays within #563's budget. Test: PR 18.
