# GDD v0.1 Phase 2: the cutover and the resource layer. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (one PR at a time, inline, as in Phase 1). Steps use checkbox (`- [ ]`) syntax for tracking. **The owner reviews this plan before any code.** Every PR below names the owner questions it waits on; a PR does not start until its questions are answered and the answers are recorded (PR 0).

**Goal:** Turn the GDD loop on for the real game in one deliberate, reviewed commit (monthly turns, re-timed event windows, every golden re-pinned once), then build the GDD's resource layer on top of it: Money as the Treasury, national Food and Arms pools, Social cohesion and International Support, event effects on all five, the D-C5 choices for the cabinet and Attention, and the HUD.

**Architecture:** Phase 1 built the GDD rules behind `systems.loop` (R-LOOP-001) and pinned them only on `MvpSlice.Overlay` (R-LOOP-003). The cutover sets `systems.loop: gdd` and `turn_lengths` all month in the real `content/eras.yaml` and `content/rules.yaml`, so the real game runs `TurnResolver` and saves name `ruleset gdd-0.1` (R-SAVE-001). From then on every PR that changes an MVP rule moves the goldens, re-pins them in the same PR and says why (spec §3, "After cutover"). The resource layer fills step 7 of the resolver (consumption, still a comment in `TurnResolver.cs`) and gives the five GDD resources a state, a rule ID and a place on the HUD.

**Tech stack:** as Phase 1: C# netstandard2.1 sim (`sim/Statecraft.Sim`), xUnit on net10.0 (`sim/Statecraft.Sim.Tests`), YamlDotNet content, Unity 6000.3.25f1 UI Toolkit (`unity/`), Python tools and policy checks under `uv`.

**Spec:** [the impact plan](../specs/2026-10-12-gdd-v0.1-impact-and-plan.md), §1.1, §1.2, §1.9, §3, §4.1 and §6 "Phase 2"; its §5 group C rows. Design of record: [docs/GDD.md](../../GDD.md). The format and the global constraints follow [the Phase 1 plan](2026-10-12-gdd-phase-1.md). Issue: #382 (part of #374); owner decisions: #375.

## Review focus

1. **The one deliberate golden move.** The cutover PR's snapshot diffs must be explainable line by line: monthly dates, the GDD sections now present in the real run, the re-timed events firing on new turns. Any moved line that none of those explains is a determinism bug, not a rebaseline. (PR 1, Task 1.6.)
2. **Old saves.** A schema 1 save and a `ruleset legacy` save are refused with one player-facing message, said once (N4), and a save from an unknown newer ruleset says it is from a newer version (N2). Never a silent replay that drifts. (Task 1.4.)
3. **Re-timed windows read wrong historically.** Every re-timed event still fires on or before the turn that covers its sourced date, unless the P59 table and the owner say otherwise, and no event text's date changes. (Task 1.3.)
4. **Resources that go negative or appear from nothing.** Food and Arms are integer pools that never go below 0 silently; a shortfall is a stated rule (owner), not a wrap or a clamp nobody chose. (PR 3.)
5. **A sensitive option that pays.** After PR 5 no option of an event tagged `holocaust`, `terror`, `massacre` or `war-casualties` can add Money, Food or Arms (the extension of `EventRules.cs:83`), whatever the owner answers on cohesion and support (Q-EFX-2). (PR 5.)
